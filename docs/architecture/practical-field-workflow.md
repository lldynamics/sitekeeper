## 入口与数据范围

项目详情「更多操作 → 现场汇报与核对」集中提供日报/周报、客户收款对账、采购催货和增项记录。沿用系统 List/Form 和现有预览/分享，不调整根导航或设备宽度策略。

- 已收口径复用正式收款优先、手填回退的算法，仅增加来源和核对提示，不相加。交付 PDF 补充毛利公式及成本来源。
- 日报按本地日历日筛选日志和明确完成日期的待办；当前进度与未完事项单列，不推算历史期末或本周新增进度。照片为用户选择的独立 PDF，缺失文件明确提示。
- 客户对账允许项目名、期间、合同、当前累计及来源、本期正式收款日期/金额、单列应收计划。不输出支出、材料/人工成本、毛利、内部财务备注、联系人或票据附件。期间与当前累计分开。
- 催货只读，材料 ID 保持独立。只累计同项目、同材料 ID、同单位的入库；未知数量或单位不符保持待核对。不自动写采购、支出或仓库流水。

## 兼容和备份

`Project.changeOrders` 为嵌套记录，旧 JSON 缺字段时为空列表，空列表不额外编码；不增加独立存储集合。

`SiteTodo.review` 为可选字段，旧 JSON 缺字段时为 nil，普通完成操作不变。复验历史和未提交备注随待办/草稿 Codable 保存；启用复验后通过才设置 isDone，提交/退回均未完成。Widget 继续读取 isDone。

新增字段随现有项目/待办完整备份往返，没有新附件所有权或文件迁移。增项只引用同项目已有资料；选择性云备份仅在副本中清除被排除的资料引用，原始记录不变。

旧版本不知道新字段，使用旧版重新导入/导出会丢弃新字段，不承诺无损降级。正式应用补丁前应保存当前版本备份；本批不执行自动历史改写或生产迁移。

## 增项保存和金额

确认仅是本机记录，不是甲方签章，不自动修改合同、财务或结算。保存以当前项目和该条记录的 expected 版本为准，复用项目保存锁，与收付计划串行。失败仅回滚本次增项，保留其他项目字段和其他增项变化；表单保留输入。
